BASELINE
--------
Install M18 only after M17 is complete and clean.

M18 GOAL
--------
Turn the working M17 REST/JNI/CUDA stack into a final release with failure
containment, capacity protection, API security, binary ingestion, runtime
diagnostics, release packaging and final project documentation.

WHAT M18 ADDS
-------------
1. Exception-based CUDA failure handling
   - CUDA_CHECK no longer calls std::exit().
   - CUDA errors become CudaException/std::exception.
   - JNI translates native failures into Java exceptions.
   - REST returns HTTP 503 without exposing native source paths.

2. CUDA diagnostics
   - GPU name
   - compute capability
   - free/total GPU memory
   - CUDA runtime API version
   - CUDA driver API version
   - native version + Git commit + dirty/clean state

3. Binary vector ingestion
   POST /api/v1/indexes
   Content-Type: application/octet-stream
   X-Vortex-Vector-Count: N
   X-Vortex-Dimension: D

   Body = little-endian IEEE-754 float32 values.

4. API hardening
   - optional X-Vortex-Api-Key
   - X-Request-ID correlation
   - request Content-Length guard
   - finite float validation
   - hardened ProblemDetail responses

5. Capacity controls
   - maximum active indexes
   - maximum persistent FP32+FP16 vector bytes
   - global concurrent GPU search semaphore
   - bounded search permit wait
   - HTTP 507 for index capacity
   - HTTP 429 for search capacity

6. Operations
   - fail-fast JNI/CUDA startup validation
   - Actuator health/info/metrics
   - resident vector-byte gauge
   - available GPU search-permit gauge
   - request logs with request IDs

7. Release engineering
   - unit tests for binary float32 decoding
   - full M18 smoke test
   - version 1.0.0
   - README + architecture/API/benchmark/security docs
   - .gitattributes line-ending policy
   - .env.example
   - release ZIP + SHA-256 manifest

MANUAL API SECURITY
-------------------
For a secured manual run:

$env:VORTEX_API_KEY = "replace-with-a-long-random-secret"

Then send:

X-Vortex-Api-Key: <secret>

If VORTEX_API_KEY is empty, API-key checking is disabled for local development.

SYSTEM ENDPOINT
---------------
GET /api/v1/system

Returns:
- M18
- native 1.0.0 version/build metadata
- CUDA GPU name
- compute capability
- free/total GPU memory
- CUDA runtime/driver versions
- active index count
- resident vector bytes
- capacity settings

BINARY INGESTION
----------------
POST /api/v1/indexes

Headers:

Content-Type: application/octet-stream
X-Vortex-Vector-Count: <N>
X-Vortex-Dimension: <D>
X-Vortex-Api-Key: <secret>  # when enabled

Body:
N * D little-endian float32 values.

See:
docs/BINARY_FORMAT.md

DEFAULT CAPACITY LIMITS
-----------------------
max vector count:          1,000,000
max dimension:             4,096
max index elements:        16,000,000
max active indexes:        8
max resident vector bytes: 1,610,612,736 (~1.5 GiB)
max concurrent searches:   2
search permit wait:        250 ms
max Content-Length:        134,217,728 (128 MiB)

These are service protection defaults, not physical GPU limits.
